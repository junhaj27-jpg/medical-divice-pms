# PMS 분석 시연

이 파일과 samples/pms-analysis-demo.csv는 모두 가상 자료다. 실제 의료기기 자료가 아니다.

1. README에 따라 설치하고 DB를 백업한 뒤 `python manage.py migrate`를 실행한다. 기존 로그인 RA_QA 또는 ADMIN을 사용한다. 새 데모 DB만 `DEMO_PASSWORD`를 지정해 `python manage.py seed_demo`로 생성한다.
2. 로그인 → 왼쪽 **PMS 분석** (`/analysis/`). UTF-8 CSV에서 `samples/pms-analysis-demo.csv`를 선택하고 **샘플 데이터**를 체크한 뒤 업로드·검증한다.
3. 수집 결과에서 승인 3건, 제외 3행을 확인한다. CSV 5행은 출처 ID 중복, 6행은 잘못된 날짜, 7행은 기기 필수값 누락이다. 파일명·수집자·생성시각·원본 SHA256을 확인한다. 원본과 raw 값은 DB에서 보존된다.
4. 분석에서 샘플, 보고일, 2026-10-01~2026-10-28, 최소 3건, 임계값 100%를 지정한다. 비교기간은 2026-09-03~2026-09-30. 현재 3건 / 비교 0건 / 증가율 미산출을 확인한다. 중대·비중대·미상 각각 1건이다.
5. **검토가 필요한 신호**의 근거를 펼쳐 내부 레코드 ID·출처·외부 ID·수집 행·원문 문장을 확인한다. 관찰 사실과 규칙 해석을 구분해 읽는다.
6. 상태를 검토 중으로, 담당자를 활성 RA_QA/ADMIN으로, 의견을 `원문 대조 후 추가 조사 필요`로 저장한다. 조치 필요로 다시 저장해 변경자·담당자·시각·상태 전후 이력을 확인한다.
7. 서버를 종료·재실행해도 동일 필터와 **저장된 검토 이력**에서 상태와 원문 스냅샷이 유지된다. 신호의 데이터/기준이 달라지면 별도 신호로 취급하며 이전 검토는 목록에서 계속 볼 수 있다.
8. 필터 결과 CSV를 열어 한글을 확인한다. 별도 파일의 기기명을 `=1+1`로 테스트하면 CSV 값에 작은따옴표가 붙어 수식으로 해석되지 않는다.
9. **분석 보고서**에서 기간·필터·출처·생성시각·통계·신호 기준·검토 내용을 확인하고 브라우저 인쇄/PDF 저장을 실행한다. `PDF_KOREAN_FONT` 설정 시 **서버 PDF**도 내려받을 수 있다.
10. 존재하지 않는 모델을 검색해 결과 없음, 실제 데이터 선택으로 샘플 제외, 잘못된 기간으로 필터 오류를 확인한다. STAFF는 분석·수집 결과·검토 이력에 접근할 수 없다.

동일 샘플 재업로드는 3건 모두 중복 제외되어 분석 보고 건수가 늘지 않는다. 시연 결과는 규제 제출 적합성이나 인과관계를 증명하지 않는다.
