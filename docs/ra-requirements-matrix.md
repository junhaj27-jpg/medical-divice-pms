# RA 플랫폼 요구사항·구현 현황

작성 기준: 현재 체크아웃 55e99ab. 작업 시작 시 git status는 깨끗했고, 기존 ERD 고도화와 0015까지의 마이그레이션이 이미 반영되어 있다. 적용 경로의 AGENTS.md는 발견되지 않았다. 아래 표는 구현 착수 전에 작성했으며 단계별 결과로 갱신한다.

| 단계 | 범위 | 현재 재사용 기능 | 착수 상태 | 이번 구현 대상 |
|---|---|---|---|---|
| 1 | 제품별 규제 프로필 | MedicalDevice, Manufacturer, RegulationDocument, RuleCitation | 미구현 | 관할·조직 역할·분류 근거·사용 범위·담당자·원문 확인 메타데이터 |
| 1 | 요구사항 매트릭스 | 규정 문서/청크, WorkTask | 미구현 | 제품/조직/조항·활동·제출물·증빙·적용 판단·충족 상태·검토 기한 |
| 1 | 인허가·갱신 | WorkTask, Notification, 증빙 검사 | 미구현 | 국가별 인허가, 신청 이벤트, 버전 제출 패키지, 갱신 업무 |
| 2 | 제품 변경 | ProductLot, CAPA, 규정 영향 분석(규칙 개정 전용) | 제품 변경은 미구현 | 제품 버전·변경 영향 체크리스트·승인 후 시행 |
| 2 | 통제 문서 | RegulationDocument는 외부 원문, Attachment는 사건 증빙 | 미구현 | SOP 등 내부 통제 문서 버전과 승인/시행/폐기 |
| 2 | 라벨·사용설명서 | UDI, 제품, LOT, 문서 버전 | 미구현 | 관할·언어별 검토·번역 의견·허가/변경·현장조치 연결 |
| 3 | 제품 위험관리 | RiskAssessment는 사건 단위 위험평가 | 제품 단위 미구현 | 승인된 제품별 수용 기준, 위해·통제·잔여위험·편익 판단 |
| 3 | 안전 정보·현장 조치 | SafetySignal, Recall/Recipient/Contact/Recovery, RegulatoryReport | 부분 구현 | 외부 정보 중복·연관성 검토, 고객안내/현장수정, 통보·효과·종결 |
| 3 | 공급자·위탁 자료 | BusinessPartner, Manufacturer, CAPA | 미구현 | 공급자 범위·승인 기준·유효기간·부족자료·변경 통보 |
| 4 | 교육·자격 | Profile/역할, WorkTask/Notification | 미구현 | 문서버전·대상자·수료 증빙·효과·재교육·영향 검토 |
| 4 | 감사·실사 | AuditLog는 시스템 행위, CAPA는 조치 | 업무 감사는 미구현 | 감사계획·지적·답변·기존 CAPA·효과확인·자료 패키지 |
| 4 | 정기 검토·경영보고 | 내부 PMS 분석/ReportArtifact | 부분 구현 | 현재 기준일 스냅샷·미결정위험·회의결정·후속 업무 |
| 공통 | 보안·무결성·문서 | 역할 검사, 보호 FK, 파일 스캔, 이력·승인 해시, ERD | 기존 구현 | 새 영역 접근 통제·명시 관계·버전 승인·보존 설정·격리 검증 |

규제 원문 내용이나 국가별 법적 기준을 자동 생성하지 않는다. 실제 최신 공식 원문을 확인하지 않은 정보는 UNVERIFIED로 등록하며 URL·확인일·확인자·적용 범위를 함께 관리한다. 예시 자료는 is_example로 분리한다. 플랫폼은 RA 업무 지원 도구이며 담당자 최종 판단과 기관 시스템 확인을 대체하지 않는다. 외부 제출·고객 발송·외부 AI 전송은 범위 밖이다.

## 구현 결과와 잔여 범위

상태는 이번 변경에서 실제 작동하는 추적 기능 기준이다. **부분 구현**은 표에 적은 제한까지 포함한다. 확인된 법률 적합성이나 실운영 승인 여부를 뜻하지 않는다.

| 범위 | 상태 | 실제 구현·기존 연결 | 미구현·제한 |
|---|---|---|---|
| 1. 제품 규제 범위 | 구현 | RegulatoryProfile, 제품/조직 역할/관할·분류·사용 목적·허가 범위·원문 출처와 담당 검토, 적용/비적용/확인 필요 | 기관별 법적 기준 데이터는 등록하지 않음. 확인 전에는 미확인 |
| 1. 요구사항 매트릭스 | 구현 | RARequirement, 내부 ID·조항/원문 버전·적용 사유·활동/제출물/증빙·담당/검토·충족/기한을 목록에서 조회 | 법적 적용 여부·검토주기는 조직 판단 입력 |
| 2. 인허가·갱신 | 구현 | MarketingAuthorization/AuthorizationEvent, 수동 외부 상태·허가조건·기한·기관 확인, SubmissionPackage 버전·접수 증빙·승인 ZIP, 명시 기한 업무/알림 | 기관 검증·전자제출 없음. 무기한 허가에 임의 만료일 없음 |
| 3. 제품 변경 | 구현 | ProductRevision/ProductChange, 변경 전후·LOT·6개 영향 영역·제출 판단/근거·검증 업무, 승인/업무 게이트·실제 시행 확인·사유 취소, 패키지 FK | 법적 제출 필요 자동 확정 없음 |
| 4. 통제 문서 | 구현 | ControlledDocument 개정/시행·폐기, 문서번호별 단일 시행본, 본문 비교·대체 연결·검사 파일·재검토 일정 | 시행본 교체는 기존 폐기와 새 시행을 명시적으로 각각 처리. 전자서명/변조불능 저장소 아님 |
| 5. 라벨·사용설명서 | 구현 | LabelVersion, 제품 버전/관할/언어/UDI/LOT/허가/변경/안전조치, 문구 변경 이유, 담당 번역 및 표시 점검·승인 | 자동 번역·국가별 법정 문구 생성 없음 |
| 6. 제품 위험 | 부분 구현 | RiskCriteria/ProductRisk, 위해·통제·검증·잔여위험·편익 판단, 수용 기준/문서 버전, 사건/신호/이상사례/CAPA, 재검토 업무 | 새 사건·신호의 관련성을 자동 판단하거나 자동 재평가 업무를 생성하지 않음. 담당자가 연결 후 재검토 업무 생성 |
| 7. 안전 정보·현장조치 | 부분 구현 | SafetyInformation의 출처·식별자 중복 제약, 수동 보고 판단·이력. FieldSafetyAction/Recipient/Contact/Evaluation, 승인 안내문·거래처/LOT·수신/완료·후속/효과·종결. 회수는 기존 원장으로 분리 | URL+식별자 외 의미적 중복 병합, 대상 대량 수신 확인, 고객 발송·기관 제출 없음 |
| 8. 공급자·위탁업체 | 부분 구현 | 기존 거래처, SupplierRecord/Material의 제조소·서비스·평가 기준·인증/계약/협약·유효기간·변경/영향·미비 자료 업무와 CAPA | 별도 부적합 전용 모듈은 없음. 외부 부적합 참조와 기존 CAPA로 연결 |
| 9. 교육·자격 | 부분 구현 | 시행 문서/역할 교육, 시도·수료·파일·효과 검증, 재교육 계보, 내 교육 접근, 역할/비활성/개정 영향 검토, 선택형 RA 승인 제한 | 입사/역할 변경 후 자동 감지는 아님. 담당자가 대상자 검토·배정 명령을 실행. 기존 PMS 권한은 유지 |
| 10. 감사·실사 | 구현 | AuditPlan/Finding/Package, 일정·체크리스트·증빙·분류 이유·답변 수정 이력·기존 CAPA·효과/종결·패키지 버전 | 외부 제출/자동 감사 평가 없음. 시스템 AuditLog와 구분 |
| 11. 정기·경영 검토 | 구현 | ManagementReview/Decision, 기존 PMS ReportArtifact, 현재 상태 캡처·기간 비교 건수·미결/기한·회의 결정/후속 업무·근거 링크·JSON | 과거 시점 상태 복원 없음. 분모가 없으면 발생률 미산정. 법정 보고서 충족을 주장하지 않음 |
| 12. ERD·보안·무결성·보존 | 부분 구현 | 모델/물리 ERD/사전, 명시 FK·조건부 unique·CHECK·잠금·승인 스냅샷·역할/CSRF·파일 검사·조직 보존 정책 | 실제 PostgreSQL/운영 자료 미검증, 조직별 로그인 테넌트 격리 없음, 자동/실제 파기 기능 없음, ORM bulk/직접 SQL은 서비스 제약 우회 가능 |

**미구현 또는 범위 제외:** 자동 기관 제출, 고객 메시지 발송, 외부 AI 전송, 법적 전자서명, 실제 자료 파기, 규정 적합성 자동 확정, 출처의 공식성/최신성 자동 확인, 운영 배포. 새 기능은 공식 규정을 내장하거나 법적 요구사항을 추측하여 등록하지 않았다.

검증·API·잔여 위험은 [RA 검증 문서](ra-verification.md), 사용 단계는 [한국어 시연 절차](ra-user-guide.md)를 참조한다.
