# RA 업무 사용·시연 절차

## 1단계: 범위·요구사항·인허가

1. RA/QA 계정으로 로그인하고 상단 **RA 업무 추적**(`/ra/`)을 연다. STAFF의 직접 URL/API 접근은 차단된다.
2. 기존 제품과 거래처(적용 조직)를 등록한 후 **제품 규제 프로필**을 만든다. 대상 국가·관할·조직 역할·제품군·분류·사용 목적을 입력한다. 확인되지 않은 기준은 **확인 필요**로 둔다. 실제 규정 원문은 기존 **보고 규칙·근거 → 규정 문서**에서 등록한다.
3. **요구사항 매트릭스**에서 내부 ID, 활동·제출물, 원문 문서·청크·조항, 적용 사유, 담당자·기한·검토 주기를 지정한다. 적용/비적용 판단에는 직접 확인한 공식 HTTPS URL·확인일·확인자를 기록한다. 플랫폼은 최신 원문을 자동 수집하거나 적합성을 판정하지 않는다.
4. **인허가·갱신**에서 국가별 프로필, 허가 종류, 번호·기관·허가일·유효기간·조건을 입력한다. 유효기간이 없으면 공란으로 둔다. 신청/보완/승인기록/반려/취하/만료/정지/취소를 수동으로 기록하면 기존 행위를 AuthorizationEvent로 보존한다. 번호만 입력해서 승인 기록으로 확정할 수 없다.
5. 해당 기록 상세 화면에서 조직이 확인한 기한으로 **기존 업무로 생성**한다. 생성된 업무는 `/tasks/`와 기존 `notify_tasks`/`notify_deadlines` 관리 명령에서 사용한다. 자동 고객 발송이나 기관 제출은 없다.
6. 프로필 상세의 **RA 증빙 등록**으로 파일을 올린다. 기존 첨부 형식·용량·검사·SHA 검증을 재사용하며 검사 통과 전 증빙 사용·다운로드를 허용하지 않는다. 악성코드 검사기를 설정하지 않으면 FAILED 상태이므로 운영자가 기존 scan_evidence 명령과 승인된 검사기를 설정해야 한다.
7. **제출 패키지**에서 동일 허가의 버전을 1부터 명시하고 목록·설명·검사 통과 파일·접수 증빙·수동 제출일을 기록한다. 담당자 검토 요청 → 지정 검토자 검토 완료 → 작성자와 다른 ADMIN 최종 승인을 수행한다. 승인 당시 목록과 파일 해시가 고정되고 수정하려면 새 버전을 등록한다. 실제 전자민원 제출은 수행하지 않는다.

각 수정에는 사유와 수정 버전이 필요하다. 다른 사용자가 먼저 수정한 행은 새로고침 후 재검토한다. DB 기록·해시는 법적 전자서명이 아니며 직접 SQL까지 변조 불가능하게 만드는 저장소도 아니다.

## 2단계: 변경·문서·표시

1. **제품 버전**에서 변경 전후 버전을 별도 등록한다. 같은 프로필에서 버전명이 중복되지 않는다.
2. **제품 변경·영향 평가**에 변경 유형과 전후 내용, 이유, 제품 버전·LOT를 지정한다. 영향 검토 JSON에는 `authorization`, `risk`, `validation`, `label`, `training`, `pms`의 6개 키에 담당자의 판단·근거 문장을 입력한다. 변경 유형만으로 법적 제출 필요 여부를 정하지 않는다. 필요/불필요를 판단하기 전에는 **확인 필요**로 둔다.
3. 검증·문서·교육 업무는 기존 WorkTask로 생성·연결한다. 최종 승인 전에 시행 확인 근거를 기록한다. 검토·승인 후에만 **변경 시행**을 처리할 수 있으며 연결 업무가 미완료면 차단한다. 시행일은 실제 처리일로 기록된다. 취소할 때는 사유를 남긴다.
4. **통제 문서**에서 SOP/작업지침/양식/기술문서, 문서번호, 버전, 본문 또는 기존 검사 통과 첨부, 시행일, 정기 검토일, 개정 이유를 입력한다. 외부 규정 원문(RegulationDocument)과 별개다. 검토 요청→검토 완료→최종 승인→시행 순서로 처리한다. 동일 문서의 시행본은 1개만 허용한다.
5. 승인 이후 문서는 편집하지 않고 상세 화면의 **새 개정 초안**으로 복제한다. 개정 전후 차이와 대체 문서가 표시된다. 기존 시행본은 사유와 함께 폐기하고 새 승인본을 시행한다. 폐기본은 과거 증빙으로 조회할 수 있지만 새로운 변경의 문서 연결에는 사용하지 않는다.
6. **라벨·사용설명서**에서 국가가 지정된 프로필, 언어·유형·버전, 통제 문서 버전, 제품 버전·허가·변경·UDI·LOT를 연결한다. 검토 JSON의 `udi`, `model`, `intended_use`, `warnings`, `precautions`를 담당자가 확인한 후 true로 지정한다. 번역 검토자·확인일·의견이 없으면 승인할 수 없다. 국가별 법적 필수 문구나 자동 번역문은 생성하지 않는다.

## 3단계: 위험·안전조치·공급자

1. **제품 위험 수용 기준**에 제품별 추정 방법·수용 기준·근거·버전을 등록하고 검토·승인한다. **제품 위험관리**는 위해요인/상황/위해, 추정 근거, 통제·검증·잔여위험·편익 판단을 별도로 기록한다. 사건 RiskAssessment의 심각도×발생가능성 계산을 이 모델에 적용하지 않는다. 관련 불만·이상사례·신호·기존 CAPA와 다음 재검토 업무를 연결한다.
2. **외부 안전성 정보**에 직접 확인한 출처·외부 식별자·수집일·검사된 원문 증빙을 기록한다. 같은 프로필에서 출처 URL+식별자는 중복되지 않는다. 제품 연관성·보고 필요 판단은 근거와 함께 수동으로 기록하며 수정 전후는 AuditLog에 보존된다. 기존 규제보고 기록을 연결할 수 있다.
3. **현장 안전조치**에서 고객 안내/현장 수정/회수를 구분하고 시행된 안내문 버전·기존 사건/CAPA/신호와 효과 확인 기준을 연결한다. 안내문을 자동 발송하지 않는다. 회수이면 기존 Recall을 반드시 연결하고 대상·통보·수량은 기존 리콜 원장만 사용한다.
4. 고객 안내·현장 수정의 대상은 **현장 조치 대상·완료**에 거래처·LOT·단위·수량으로 등록한다. 조치 승인 후 대상 계획은 변경하지 못한다. 조치가 시행된 뒤 편집 화면에서 수동 통보일·수신 확인·완료 누계·완료일·결과 근거를 기록한다. 상세 화면에서 후속 연락 사실을 추가하고 미응답·미조치에는 기존 업무를 연결한다.
5. 진행 중 조치의 상세에서 효과 판정·근거·검사된 증빙 ID로 평가를 추가한다. 관리자는 최신 평가가 효과 확인이고 미응답/미조치 대상이 없을 때 종결한다. 회수는 기존 리콜 종결도 확인한다. 평가·연락 이력은 새 행으로 남는다.
6. **공급자·제조소·위탁업체**는 기존 BusinessPartner를 참조하며 공정·서비스·조직 평가 기준·필요 시 승인 문서·다음 검토일을 기록한다. **공급자 규제 자료**에 인증서/계약/품질협약·버전·유효기간·미비·변경 통보·영향 검토·증빙을 연결한다. 일률적 갱신일은 생성하지 않는다. 미비·기한 임박 자료에 기존 업무를 생성한다. 관련 CAPA는 기존 사건 CAPA를 연결하고 별도 중복 CAPA를 만들지 않는다.

## 4단계: 교육·감사·정기 검토

1. **역할별 교육·자격 기준**에서 시행 문서의 정확한 버전, 역할, 기한, 효과 확인 방법을 등록·승인한다. 상세의 **활성·역할 기준으로 교육 대상 검토·배정**은 대상 사용자를 명시적으로 검토해 중복 없이 배정한다. 신규 입사자는 다음 실행 때 배정하며 비활성·역할 변경은 기존 이력을 삭제하지 않고 비활성/영향 검토 상태로 남긴다.
2. STAFF는 **내 교육**(`/my-training/`)에서 본인에게 배정된 문서만 읽을 수 있다. 열람해도 완료로 바뀌지 않는다. RA 담당자가 **교육·수료·재교육**에서 수료일·검사된 증빙·효과 PASS·근거를 기록해야 수료 확인된다. FAIL은 재교육으로 남기고 새 기준/교육 계획과 연결한다. 프로필 상세의 영향 대상 목록으로 문서 개정·역할 변경 대상을 검토한다.
3. 교육 미완료자의 업무 제한은 기준의 **명시적 제한**을 조직이 켰을 때만 신규 RA 최종 승인에 적용한다. 기본은 꺼짐이며 기존 PMS 승인 권한을 변경하지 않는다. 문서 열람을 전자서명·교육 효과 확인으로 해석하지 않는다.
4. **감사·실사 계획**에 일정·범위·조직 기준·체크리스트·증빙을 기록한다. **관찰·지적·답변**에서 분류와 근거·기한·답변·수정 내용을 보존하고 필요한 경우 기존 CAPA를 연결한다. 답변·효과 확인과 연결 CAPA 완료를 검토한 뒤 승인·종결한다. 시스템 **AuditLog**와 업무 감사는 서로 다른 용도다.
5. **감사 제출 자료 패키지**는 감사별 버전을 보존하고 검사된 파일과 수동 제출/접수 참조를 지정한다. 검토·승인 시 목록과 해시를 고정한다. 자동 기관 제출은 없다.
6. **정기 검토·경영 보고**에서 기간·기준 프로필·미해결 위험·회의 의견을 입력하고 상세의 **현재 상태·기간 집계 캡처**를 실행한다. 기간 내 불만 보고 건수, 캡처 시점의 인허가/변경/문서/교육/공급자/감사/안전조치/위험/기한 초과 업무를 링크와 함께 저장한다. 과거 시점 상태 복원으로 표현하지 않으며 분모가 없는 발생률을 계산하지 않는다. 기존 PMS ReportArtifact를 연결할 수 있다.
7. **회의 결정·후속 조치**에 담당자·결정·근거·기한을 등록하고 기존 업무를 생성한다. 승인 후 후속 업무·결과·완료를 확인해 종결한다. **조직 보존·파기 정책**에서 근거·확인일·조직 보존 기준을 기록한다. 기간을 모르면 공란이며 자동 삭제는 DB 제약으로 비활성 상태만 허용한다. 실제 파기는 별도 조직 검토 범위다.

## 설치·격리 시연 (Windows PowerShell)

요청 저장소에서 실행한다. 운영 DB·미디어에는 적용하지 않는다. `python`은 Django 의존성을 설치한 가상 환경의 명령으로 바꿔도 된다. 아래 명령은 별도 폴더를 사용한다.

```powershell
Set-Location -LiteralPath 'C:\Users\정준하\Documents\Codex\2026-10-30\https-github-com-junhaj27-jpg-medical\work\medical-divice-pms'
python -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -r requirements.txt
$Python = (Resolve-Path .\.venv\Scripts\python.exe).Path
$RaSandbox = Join-Path (Get-Location) 'work\ra-platform\local-demo'
New-Item -ItemType Directory -Force -Path $RaSandbox | Out-Null
$env:DB_ENGINE = 'sqlite'
$env:SQLITE_PATH = Join-Path $RaSandbox 'demo.sqlite3'
$env:PRIVATE_MEDIA_ROOT = Join-Path $RaSandbox 'media'
$env:PMS_STATIC_ROOT = Join-Path $RaSandbox 'static'
$env:PDF_KOREAN_FONT = 'C:\Windows\Fonts\malgun.ttf' # 실제 파일이 있는 경우
& $Python manage.py check
& $Python manage.py makemigrations --check --dry-run
& $Python manage.py showmigrations --plan
& $Python manage.py migrate --noinput
& $Python manage.py test --noinput
& $Python manage.py collectstatic --noinput
git diff --check
& $Python manage.py createsuperuser
& $Python manage.py runserver 127.0.0.1:8000
```

관리자에서 서로 다른 작성자와 승인자 계정 및 RA_QA/ADMIN 프로필을 만든다. 기존 제품과 거래처를 등록한다. 로컬 `/ra/`에서 위 순서대로 `TEST` 제목 및 **예시 자료**를 선택해 시연한다. 공식 원문 확인이 없으면 실제 법적 기준 필드를 채우지 않는다. 사용자/파일·기한은 조직이 직접 입력한다. 파일 검사기는 기존 `ANTIVIRUS_COMMAND` 설정을 사용하며, 실검사 도구 없이 검사 통과를 임의로 처리하지 않는다.

예시 검토 기한을 입력한 후 명령으로 업무·내부 알림을 준비할 수 있다. 실제 로그인 사용자의 실행 행위를 기록하기 위해 활성 RA/QA 또는 ADMIN 사용자명을 지정한다.

```powershell
& $Python manage.py plan_ra_reviews --actor raqa --horizon-days 30
& $Python manage.py notify_tasks
& $Python manage.py scan_evidence
```

등록한 날짜만 사용한다. 위 명령은 외부 전송·제출·자동 파기를 하지 않는다. 인허가 또는 적용 판단이 달라지면 **사유 있는 재검토 개시**로 초안에 되돌리고 새 상태/근거를 기록한다. 이전 승인 스냅샷과 허가 이벤트는 남는다. 제품 변경 승인 이후 **시행 확인**에서 실제 확인 내용을 기록한다. 교육 재시도는 동일 교육 기준/대상자, 이전 시도 연결, 증가한 시도 번호로 등록한다.

승인된 제출/감사 패키지는 상세의 **승인된 제출 패키지 ZIP**으로 목록 JSON과 검사된 증빙을 다운로드한다. 해시 불일치 시 중단한다. 정기 검토의 기간 비교는 동일 길이의 이전 기간에 대한 신규 불만·CAPA·신호 건수이며 발생률이 아니다.
