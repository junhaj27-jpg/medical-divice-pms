# 가상 뇌파 제품으로 RA 실무 시연

격리된 DB에서 RA/QA 작성자, 검토자, 별도 ADMIN 승인자를 준비합니다. 예시는 환자나 회사 자료가 없는 가상의 **모의파형 분석기 DEMO-EEG-SW**와 **모의파형 수집기 DEMO-EEG-HW**입니다. 각각 기존 제품과 예시 규제 프로필을 등록하고 하위 기록의 예시 표시를 동일하게 설정합니다. 관할과 법적 적용 여부는 확인 필요로 둡니다.

공통 흐름은 RA 메뉴에서 등록하고 검토 요청, 검토 완료, 최종 승인 순서로 처리하는 것입니다. 승인된 본문과 실행 결과를 바꾸려면 새 버전 또는 별도의 정정·재시험 기록을 만듭니다. 기존 증빙 화면에서 해당 규제 프로필에 파일을 올립니다. 실제 시연에서는 설정된 검사기가 통과시킨 원본을 선택합니다.

## 1. GMP 계층과 기록

1. 통제 문서에 QMD-01 품질매뉴얼, SOP-01 절차, WI-01 지침, FRM-01 v1 양식을 생성합니다. 각 문서를 검토·승인하고 시행일에 시행합니다.
2. GMP 문서 계층에서 위 순서대로 상위 문서를 연결합니다. 부서, 관련 요구사항, 교육 기준을 지정합니다. 양식의 필수 항목 배열은 ["device_code","lot","review_result"]처럼 입력합니다. 승인된 템플릿 표시와 계층 기록 승인을 완료한 후 새 문서번호로 초안을 복제할 수 있습니다.
3. GMP 양식 작성 기록에서 고유 기록 키, 현행 양식 정의, LOT, 기한과 기존 업무를 연결합니다. 값을 비워 두면 누락 항목이 표시되며 필수 항목이 빠진 상태에서는 승인할 수 없습니다. GMP 누락·기한 현황에서 미작성, 기한 경과, 미승인 정의와 정기 검토 기한 경과를 조회합니다.
4. FRM-01 v2를 시행하고 v1을 폐기합니다. v1 신규 작성이 차단되고 v1 원기록이 조회되는지 확인합니다. 정정이 필요하면 새 키의 기록에 v1 원기록과 동일한 양식 정의를 연결해 값과 정정 사유를 남깁니다. 이전 본문과 승인 이력은 원기록에서 조회합니다.

## 2. 품질경영용 시스템 밸리데이션

1. **모의 GMP 기록 추적기 QMS-DEMO 1.0**의 사용 목적, 품질 영향, 계획, 수용 기준을 등록합니다. 제품 소프트웨어 검증은 DHF의 별도 검증 문서로 연결합니다.
2. 요구사항에 “양식 버전과 원기록을 추적한다”, 위험에 “개정 시 과거 값 분실”, 통제에 “정정 기록에서 원기록 FK를 유지한다”를 입력합니다.
3. 요구사항과 시험 케이스 v1을 승인한 후 실행 결과를 등록합니다. 미실행은 실행 기록이 없는 상태입니다. 실패와 면제는 선택이 다르며 사유가 필요합니다. PASS/FAIL에는 검사를 통과한 실행 증빙을 연결합니다.
4. 실패한 실행을 바꾸지 않고 이전 실행에 연결된 재시험을 추가합니다. 면제를 선택한 실행은 승인 후에만 최종 검토 조건을 충족합니다. 시험 케이스를 변경하면 버전 2를 작성해 승인하고 새 실행을 연결합니다.
5. 공급자 자료가 있으면 기존 공급자 자료를 참조하고 내부 확인은 별도 필드에 기록합니다. 결과 보고서 검토 시 요구사항별 최신 케이스와 실행·일탈을 확인합니다. 변경 후 평가에는 이전 밸리데이션을 연결하고 재검토 사유를 작성합니다.

## 3. 회의록 후보와 DHF

1. DEMO-EEG-SW의 가상 출시 버전 v2와 DHF 프로젝트를 등록합니다. 통제 문서에 EEG-SPEC v1을 준비합니다. 같은 프로필에 아래 내용을 UTF-8 TXT로 올리고 검사 후 회의록 원문에 연결합니다.

        설계 출력 EEG-SPEC v1 담당: 합성 검토팀, 2026-11-10
        위험 미해결: 결측 구간 표시 방법 검토
        후속: 누락된 검증 문서 확인

2. 회의록에서 후보 추출을 두 번 실행합니다. 같은 행의 후보가 늘어나지 않는지 확인합니다. 후보 상세에서 원본 파일, 행 번호, 발췌, 담당·기한 후보, 문서/파일 일치 여부를 검토합니다. 파일명이나 문서 버전이 모호한 경우 미확인 상태를 확인합니다.
3. 확인된 후보를 검토·승인한 후 DHF에 연결합니다. 원문 언급은 실제 검증 완료나 설계 승인을 기록하지 않습니다. 필요한 후속 업무는 연결 확인 후 기존 업무 생성 기능으로 지정합니다.
4. 설계 추적 행에서 요구사항, 출력, 제품 위험, 검증 문서, 변경, 출시 버전을 선택합니다. 프로젝트의 원문·증빙 링크, 연결 누락·미검토·구버전 표시를 확인합니다.
5. 기준 스냅샷을 생성하고 승인합니다. 현재 프로젝트 또는 저장된 기준을 CSV와 PDF로 내보냅니다. 한글 PDF에는 기존 PDF_KOREAN_FONT 설정을 사용합니다. 표는 연결과 검토 상태를 나타냅니다.

## 4. 변경심사 준비

1. 기존 제품 버전 DEMO-EEG-SW v1과 v2, 제품 변경 요청과 DHF v2 프로젝트를 연결합니다. 기능 비교는 “고정 필터에서 시험용 선택 필터로 변경”, 알고리즘 비교는 “합성 데이터에서만 검토한 필터 경로”, 목적 비교는 “가상 교육·시연 범위”를 사용합니다. 출시 승인 및 시행 이력은 기존 제품 버전에서 조회합니다.
2. 변경심사에서 담당자 분류와 판단 근거를 작성합니다. 법적 분류를 확인하지 않았다면 확인 필요로 둡니다. 실제 기준을 등록하는 업무에서는 조직이 최신 공식 출처를 직접 확인하고 기존 규정 문서의 버전·확인일과 근거를 기록합니다.
3. 기술문서 목차별 시행 문서, 담당자, 증빙을 연결하고 준비 상태를 확인합니다. 승인된 제출 패키지에는 동일 변경 요청과 출시 버전, 제출 파일을 연결합니다. 변경심사 승인 시 목차 문서 버전·해시, DHF 스냅샷, 패키지 해시를 기록합니다. 기존 제출 패키지 상세에서 ZIP을 내려받아 검토할 수 있습니다.
4. 심사 질의와 답변을 등록하고 해당 제출 버전을 연결합니다. 보완 답변은 이전 답변과 연결된 새 기록으로 작성합니다. 수동 접수 정보는 기존 제출 패키지에 기록합니다.

## 5. 사이버보안 검토

1. v2 출시 버전의 자산과 외부 인터페이스를 기록합니다. 아래 CSV를 동일 프로필의 증빙으로 검사한 후 SBOM 가져오기를 실행합니다.

        name,version,source
        demo-filter-lib,1.0,synthetic-local
        demo-viewer,2.0,synthetic-local

2. 취약점은 가상 식별자 DEMO-VULN-01, 출처 “합성 테스트”, 확인일, 위협 시나리오와 영향 근거로 수동 등록합니다. 외부 점수를 기록할 경우 원래 점수와 출처·버전을 함께 입력합니다. 제품 위험·기존 CAPA·변경·현장 조치에서 해당하는 자료를 연결합니다.
3. 담당자·기한·패치·잔여위험을 기록하고 조치 증빙을 연결합니다. 구성 목록 검토 후 출시 보안 시험 계획·결과·증빙을 기록합니다. 미해결 항목이 있으면 조치 계획과 판단 근거를 남기고 별도 승인자로 검토합니다.

## 범위와 제한

| 범위 | 상태 | 적용 범위 |
|---|---|---|
| GMP 문서 계층·양식·기록 정정 | 구현 | 시행 통제 문서 재사용, 필수 값, 원본 보존, 승인 템플릿 초안과 기한 현황 |
| 기록 관리 AX | 부분 구현 | 로컬 자연어 집계와 원본 링크. 업무별 예정 기록은 담당자가 등록하며 GPT Work 연동은 미구현 |
| 품질시스템 밸리데이션 | 구현 | 요구사항·위험·시험 버전·실행·일탈·재시험·면제 승인과 검토 스냅샷 |
| 회의록 추출 | 부분 구현 | 검사된 UTF-8 텍스트의 행·키워드·문서번호/버전·첨부명 일치. PDF/OCR와 첨부 본문의 자동 추출은 미구현 |
| DHF 추적 | 구현 | 기존 문서/위험/변경/출시 연결, 상태 표시, 기준 캡처, CSV/PDF |
| 변경심사 | 부분 구현 | 담당자 분류·기술 목차·질의/답변·버전·해시 추적. 제출 파일의 편성은 기존 패키지에서 수동으로 수행 |
| 사이버보안 | 부분 구현 | 수동 기록·CSV SBOM·시험·조치·출시 보안 검토. SPDX/CycloneDX 네이티브 파서와 자동 외부 수집은 미구현 |

공식 규제 기준 데이터는 이번 예시에 등록하지 않았습니다. 이 시연의 판단 근거는 모두 합성 자료입니다. [격리 실행 명령과 RA 기본 사용법](ra-user-guide.md)

실무 화면은 기존 RA/QA와 관리자 접근 범위를 사용합니다. 작업자 전용 양식 작성 화면은 추가하지 않았습니다. 회의록 후보 검색은 원본의 첫 5,000행을 대상으로 하며 발췌는 행당 최대 4,000자입니다. SBOM CSV는 최대 5,000개 구성요소를 읽습니다.

GMP 작성 기록의 프로젝트 항목에서 같은 제품 규제 프로필의 DHF 프로젝트를 선택할 수 있습니다.
