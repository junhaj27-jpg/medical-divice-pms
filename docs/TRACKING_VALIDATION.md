# 6~9순위 구현·검증 보고

작업 대상: medical-divice-pms. 기존 구현을 확인한 뒤 공통 설계를 기록하고, 6·7순위 테스트 통과 후 8·9순위를 구현했다. 운영 데이터 시드·기존 DB 변경·외부 제출은 수행하지 않았다.

## 공통 상태와 승인 범위

공통 설계는 TRACKING_DESIGN.md에 기록했다. 화면과 API는 동일한 도메인 서비스 함수를 호출한다. 신규 감사 이벤트는 ID·상태·해시를 기록하며 조사 원문, 제출자 문자열, 증빙 원문, 중복 판단 근거를 감사 로그에 복제하지 않는다.

신호: 조사/연결/효과 확인은 기존 NEW/REVIEW/ACTION/CLOSED 상태와 연결된다. 종결 예외는 제공하지 않고 미완료 조치가 있으면 차단한다. 조치 불필요 판단 없이 무조치 종결할 수 없다. CAPA 효과는 기존 평가의 날짜·결과·증빙을 참조한다. 리콜 효과 확인은 별도 날짜·결과·증빙을 기록한다. 신호는 인과관계 확정으로 표시하지 않는다.

제출: PREPARED → SUBMITTED → ACKNOWLEDGED 또는 SUPPLEMENT_REQUESTED → SUPPLEMENT_SUBMITTED → ACKNOWLEDGED/추가 보완/COMPLETED. 보완 제출은 새로운 SubmissionVersion을 요구한다. 제출·보완 제출에는 사용자의 confirm=true와 실제 제출 일시·제출자가 필요하다. 접수번호·PDF만으로 승인이나 적합성을 확정하지 않는다.

승인 대상은 기존 approval_integrity.FIELDS에 제출 기관·경로를 추가한 허용 목록이다. 보고 내용·판단·제출 계획 변경은 재승인과 새 PDF 생성을 요구한다. 접수번호·접수증·보완 요청·행정 처리 상태·후속 기한은 승인 대상과 분리한다. ADMIN 용도 증빙 추가만으로 기존 임상 승인을 무효화하지 않는다. 기존 승인도 승인 대상 필드 확장으로 재승인이 필요할 수 있다.

보고서: DRAFT 스냅샷 검토 후 명시적 확인으로 FINAL 새 버전을 생성한다. 최종본은 덮어쓰지 않는다. 수정은 새 초안을 만든다. 기간 내 발생은 occurred_on 기준이며 현재 업무 상태는 생성 시각 기준이다. 과거 상태 복원을 주장하지 않는다. 내부 사건·CSV·내부 가져오기 코호트는 합산하지 않는다. CSV 제품 매핑은 제조사·제품명·모델 정확 일치 기준이며 누락/불일치 자료는 해당 제품 통계에 포함되지 않는다.

중복: 의심 관계는 통계를 변경하지 않는다. ADMIN의 EXCLUDE/INCLUDE만 앞으로 계산하는 안전 신호·내부 분석·정기 보고서에 반영한다. 기존 PDF·확정 보고서·저장된 신호 근거는 변경하지 않는다. 직원은 본인이 접근 가능한 후보와 이력만 볼 수 있다.

## 미검증·운영 반영 전 확인

- 실제 PostgreSQL 행 잠금·교착·다중 프로세스 부하: 현재 SQLite 환경에서는 검증하지 못했다. 기존 PostgreSQL 전용 테스트 6개는 건너뛰며, 새 동시 요청 테스트는 SQLite에서 실행했다.
- 브라우저 수동 조작·시각적 레이아웃·운영 규모 성능은 검증하지 않았다. Django 클라이언트로 화면 렌더링·상태 코드와 API 동작을 검증했다.
- 운영 DB 마이그레이션 적용, 실제 기관 포털 제출·접수, 법정 PSUR/PMS 적합성 검증은 수행하지 않았다. 자동 제출 기능은 없다.
- 후속 기한은 사유 있는 수동 입력을 지원한다. 승인된 규칙을 이용한 자동 후속 기한 생성은 추가하지 않았다.

## 사용 경로

- 안전 신호 상세 → 조사·조치·효과 추적: /safety/signals/{id}/tracking/
- 규제보고 목록 → 제출·보완 추적: /reports/{id}/tracking/
- 불변 제출본과 이벤트: /submissions/{id}/
- 내부 PMS 정기 검토: /pms-reviews/
- 사건 접수 후 후보 안내 또는 사건 상세 → 입력 중복·데이터 품질 검토함: /complaints/{id}/duplicates/
- 동일 기능 API: /api/safety/signals/{id}/tracking/, /api/reports/{id}/tracking/, /api/submissions/{id}/tracking/, /api/pms-reviews/, /api/complaints/{id}/duplicates/

독립 검토 단위는 0015_safety_investigation, 0016_regulatory_submission, 0017_periodic_review, 0018_duplicate_review 마이그레이션과 해당 서비스 모듈이다.


문서 비교 후 보완: 내부 가져오기 활성 집계에도 ADMIN 확정 제외를 적용한다. 별도 전체 보존 스냅샷 수는 제외 사건·정정 전 버전을 포함하는 보관 현황이며 사건 건수나 활성 집계와 합산하지 않는다. 기존 확정본은 재계산하지 않는다. 보존 기록의 불변 보호는 정상 애플리케이션·일반 ORM 경로에 한정되며 직접 SQL·DB 관리자·외부 파일 변조 방지나 전자서명 보증이 아니다. 상세 변경과 이번 검증 주체는 [문서 비교 후 수정](TRACKING_REVIEW_FIXES.md)을 따른다.
