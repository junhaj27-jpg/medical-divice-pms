# 문서 비교 지적 사항 수정

2026-11-01 (Asia/Seoul). 비교 기준은 `537530b` 위의 6~9순위 작업 트리다. 기존 변경을 보존한 채 독립 문서 비교 보고서의 지적 1~5를 반영했다. 운영 DB 적용·배포·실제 기관 제출은 수행하지 않았다.

## 코드 수정

1. **내부 가져오기 활성 집계의 제외 누락**: `pms/periodic.py`의 최신 내부 코호트에도 원본 사건의 ADMIN 확정 제외를 적용한다. 단순 의심은 계속 포함한다. 예시 구분은 원본 사건과 분석 배치 양쪽에서 검사한다.
2. **보관 현황 분리**: 내부 가져오기 전체 보존 버전 수를 별도 항목으로 제공한다. 제외 사건·정정 전 버전도 포함하지만 사건 발생 건수나 활성 집계와 합산하지 않는다. 수치 단위를 스냅샷으로 표시하고 포함 기준과 근거 목록을 함께 보존한다. 기존 확정 보고서의 스냅샷은 변경하지 않는다. 구버전 표시 필드가 없는 보고서는 기존 단위로 렌더링된다.
3. **보존 기록의 일반 ORM 우회 방지**: 공통 `FrozenRecord` 관리자가 QuerySet.update/delete, bulk_update 및 충돌 갱신 bulk_create를 거부한다. 신호 조사·제출본·제출 이벤트·정기 보고서·중복 검토 이력에 공통 적용한다. 새 기록 추가와 요청 키 재시도는 유지한다. 스키마 변경은 없다.

직접 SQL·DB 관리자·외부 파일 변경을 차단하는 외부 불변 저장소 또는 전자서명을 추가한 것은 아니다.

## 문서 수정

- README·운영·규제·승인·기존 검증·개발 계획·과거 독립 검증 문서에 현재 진입점과 `0018_duplicate_review` leaf를 연결했다. 과거 결과는 삭제하지 않고 해당 단계의 기록이라고 구분했다.
- 승인 안내에 CONTENT/ADMIN 용도, 용도 변경 금지, 기관·경로의 승인 대상 포함, 제출 후 행정 메타데이터 제외, 기존 해시 재승인 가능성을 반영했다.
- 운영·규제 안내에 새 화면 경로, 수동 제출 확인, 보고 판단 상태와 실제 제출 이벤트의 차이를 추가했다.
- 새 설계·검증 문서에 활성 집계와 보존 스냅샷의 차이 및 불변 보호의 애플리케이션 범위를 명시했다.
